Cross-platform design tokens NDA

One design language for Web, iOS and Android in a fintech product: a shared token set, the same names on every platform, and a rebuilt component library.

Company
Garage IT
Role
Lead Product Designer
Platform
Web, iOS, Android
Timeline
6 weeks design, 4 weeks development

Context

The iOS app was close to release, the Android app was already live, and the web was in the middle of a redesign. The three platforms looked like three different products.

The same element had a different name, color and size on each platform. Every new screen had to be designed and explained three times, and the differences kept growing with every release.

Three levels of tokens

Primitives hold raw values. Semantic tokens say what a value means. Component tokens say where it is used. Light and dark themes and different brands switch at the semantic level, so components never need to know which theme or brand they are in.

One token, three platforms

Tokens live in Figma Variables and are exported to JSON in the project repository. From there each platform gets the same token under the same name. A designer and a developer on any platform now use the same word for the same thing.

Components

I rebuilt about 60 components on top of the new tokens and put together the design system in Figma and in Storybook.

Platforms were allowed to differ only where a native element serves people better. Everything else is shared: the same structure, states and names on Web, iOS and Android.

Working with engineering

The system only works if it lands in code the same way everywhere, so I worked closely with the Web, iOS and Android leads on naming, token structure and how tokens get into each codebase. We aligned even the animations, so a component moves the same way on every platform. Every component was tested on all three platforms before it went to production.

Beyond the product

The design system was aligned with other projects inside the company. Its token structure, naming and process were adopted at the company level.

Takeaway

Setting the system up took real time from design and engineering. It paid off on every screen after that: design got more than twice as fast, and releases went out on all platforms on schedule.
